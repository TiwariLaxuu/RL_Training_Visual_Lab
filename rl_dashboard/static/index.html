The RL loop

Everything below is one repeated exchange between an agent and an environment: the agent observes a state, takes an action, and gets back a reward and a new state. Train this loop enough times and it converges toward a policy that maximizes total reward.

Return: what "maximize the result" actually means

The GridWorld demo had one fixed target square — but the general RL objective doesn't require a fixed goal at all. The agent maximizes the expected discounted return: the sum of all future rewards, discounted so sooner rewards count more than later ones.

Gt = Rt+1 + γRt+2 + γ²Rt+3 + ... = Σk=0∞ γk Rt+k+1

γ (gamma, 0–1) is the discount factor. "Reach the goal" is just a special case where reward is 0 everywhere except one state — the same equation covers balancing a pole, landing a rocket, or playing chess indefinitely.

Bellman expectation equations value of following a fixed policy π

State-value function — how good is it to be in state s if I keep following π?

Vπ(s) = 𝔼π[ Rt+1 + γVπ(St+1) | St=s ]

Action-value function — how good is it to take action a in state s, then follow π?

Qπ(s,a) = 𝔼π[ Rt+1 + γQπ(St+1,At+1) | St=s, At=a ]

Both are recursive: the value of "now" is defined in terms of the value of "one step later." That recursion is exactly what let the GridWorld Q-table bootstrap itself from zero.

Bellman optimality equations value of the best possible policy

Swap "follow π" for "always take the best available action," and you get the equations that define the optimal value functions V* and Q* — not tied to any one policy:

V*(s) = maxa 𝔼[ Rt+1 + γV*(St+1) | St=s, At=a ]
Q*(s,a) = 𝔼[ Rt+1 + γ maxa' Q*(St+1,a') | St=s, At=a ]

Q-learning's update rule (from the GridWorld video) is literally this equation, applied one sampled transition at a time instead of over the true expectation.

From a table to a network: why this needs gradient descent

A table only works while (state, action) pairs are countable — 25 grid squares × 4 moves. CartPole's state is 4 continuous numbers; most real environments have effectively infinite states. So instead of a table, we use a neural network Qθ (or a policy network πθ) with weights θ, and train θ so the network satisfies the Bellman equation approximately.

L(θ) = 𝔼 [ (y − Qθ(s,a))² ] ,   y = r + γ maxa' Qθ(s',a')

This is the same TD-error idea as the GridWorld update — y is the "target" the network is nudged toward. What's different is how θ gets nudged: not a single table cell, but every weight in the network, via gradient descent.

Policy gradient theorem what PPO/A2C actually optimize

Value-based methods (DQN) learn Q and act greedily. Policy-based methods instead directly adjust a network that outputs actions, by pushing up the probability of actions that led to higher return than expected:

∇θ J(θ) = 𝔼πθ [ ∇θ log πθ(a|s) · Aπ(s,a) ]

A(s,a) is the advantage: how much better action a was than average at state s (≈ Q(s,a) − V(s)). PPO adds a clip so this update never moves the policy too far in one step:

LCLIP(θ) = 𝔼 [ min( rt(θ) At,   clip(rt(θ), 1−ε, 1+ε) At ) ]

That's exactly the train/policy_gradient_loss, train/clip_fraction, and train/approx_kl numbers streaming in on the Train tab while PPO runs.

How reward actually drives training

The reward never touches the network weights directly. What actually happens, every update:

  1. The agent collects a batch of (state, action, reward, next_state) transitions by acting in the environment.
  2. Rewards are combined across a trajectory into a return or advantage — "was this action better or worse than expected, accounting for everything that happened afterward?"
  3. That advantage becomes part of a loss function (see the Algorithm card below for the exact one this run used).
  4. Gradient descent then adjusts every weight in the network to reduce that loss — nudging the network toward actions that led to higher-than-expected reward, and away from ones that didn't.
  5. Repeat with the (now slightly better) policy. The next batch of rewards reflects the updated behavior — that's the feedback loop that gets you from a random policy to a good one.

In other words: reward → advantage/target → loss → gradient → weight update → different behavior → different rewards next time. See the Math Lab tab for the exact equations.
